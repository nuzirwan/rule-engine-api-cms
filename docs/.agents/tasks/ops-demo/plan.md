## Grounding facts discovered during exploration
- `internal/httpapi/server.go` `NewHandler(store Store, interp *flow.Interpreter, deps Deps)` registers EXACTLY one route: `GET /orders/{id}` (no admin routes mounted here, despite the task prose). `NewServer(addr, store, interp, deps)` wraps it.
- `httpapi.Deps{Conns connect.Registry; Decide decision.Evaluator; Trace observ.Tracer; Log observ.Logger}`. `httpapi.Store` is a 1-method interface (`ActiveFlow`). The handler needs `config.Store` for readiness `Ping`.
- `connect.Registry.HealthCheck(ctx) error` already exists (fans out `ping` to every client). `config.Store.Ping(ctx) error` already exists on both `*memStore` (always nil) and `*PgStore` (pings pools).
- `internal/observ` has `NewMetrics(reg prometheus.Registerer) *Metrics` but is NOT wired anywhere and there is NO promhttp import yet. `github.com/prometheus/client_golang` is already a dependency (promhttp is in that module).
- `cmd/engine/main.go` builds `tracer, obsLog, store, registry, engine, interp` then calls `httpapi.NewServer(addr, store, interp, httpapi.Deps{...})`. `store` is a `config.Store`.
- Seed load (`config.SeedFromBytes`/`LoadSeed` for memStore, `config.SeedPgStore` for PgStore) does NOT run `ValidateTree`; the runtime interpreter does not either. So seed trees need only be runtime-valid, not admin-validate-valid.
- Flow runtime semantics (`internal/flow/handlers.go`, `control_handlers.go`): `action` and `set` call `walkChildren` (run their children in order). `decision` (`decisionHandler`) runs the JDM, stores the WHOLE output map under `SaveAs` in `Ctx.Data`, and is TERMINAL — it ignores its own children. Therefore the `response` must NOT be a child of a `decision` node.
- ZEN output: `zenCompiled.Eval` unmarshals `resp.Result` to `map[string]any`; a decisionTableNode with output field `action` yields `{"action":"..."}`. `httpapi.branchingEvaluator` only ADDS a `branch` key when the map has a single string value — harmless for a decision node; `decided.action` still resolves.
- `templatingClient.normalizeResult` unwraps a single pg row (`[]map[string]any` len 1) to a map, so `order.<col>` resolves after `saveAs:"order"`.
- Postgres driver (`internal/connect/drivers/postgres.go`) uses POSITIONAL params `$1`, kind `"query"`, payload `{sql, params}`. A schema-qualified table name in the SQL is honored verbatim (no search_path rewrite).
- cmd/engine env (`.env`): `CONFIG_DSN` → config store (schema `rule_engine` default), `VALKEY_ADDR` optional. New data-source DSN env to add: `ORDERS_PG_DSN` already documented in `.env.example`; this task reuses/overrides the data-source connection via env (decision below).

## Design decisions (made here, not deferred)
1. **Readiness needs the config store, not just the httpapi.Store subset.** Add a 1-method `Pinger` interface (`Ping(ctx) error`) in `internal/httpapi` and thread a `config.Store` (which satisfies it) via `Deps`. Rationale: minimal new seam, both store impls already satisfy it, keeps httpapi free of a hard `config` import for the ops path (the interface lives in httpapi).
2. **Metrics registerer threading.** Add `Metrics *observ.Metrics` and a `prometheus.Gatherer` to `Deps` is heavier than needed; instead add `MetricsHandler http.Handler` to `Deps` (nil ⇒ `/metrics` not mounted) built by the caller from the same registry the RED metrics use. Rationale: keeps `internal/httpapi` from importing prometheus directly beyond the handler type; the one place that owns the registry (cmd/engine) builds `promhttp.HandlerFor(reg, ...)`. The ops handlers for livez/readyz live in `internal/observ` per the task ("internal/observ has no HTTP ops handlers"); `/metrics` is `promhttp` exposed through the same package via a thin constructor.
3. **Ops HTTP handlers home.** New file `internal/observ/ops.go` exports `LivezHandler()`, `ReadyzHandler(reg Readiness, store Pinger)` and `MetricsHandler(gatherer prometheus.Gatherer) http.Handler`, where `Readiness`/`Pinger` are tiny interfaces (`HealthCheck(ctx)`, `Ping(ctx)`) satisfied by `connect.Registry` and `config.Store`. Rationale: the task says the ops HTTP handlers belong in observ; keeping the gating interfaces local avoids observ importing connect/config.
4. **Two flows share ONE JDM** `fmc-decision`: single decisionTableNode, one input `payment_status`, one output `action`; rule1 `payment_status == 'PAID' ⇒ 'proceed_fulfillment'`, rule2 (catch-all) ⇒ `'await_payment'`.
5. **Data-source connection** key `fmc-pg`, type `postgres`, DSN overridable by env. **Decision: reuse `ORDERS_PG_DSN`** (already documented in `.env.example`) as the single env knob, default `postgres://root:root@127.0.0.1:5432/fmc_utility?sslmode=disable`. Rationale: avoid introducing a second near-identical env var; document clearly. The seed carries the default DSN; cmd/engine overrides `fmc-pg` settings `dsn` from `ORDERS_PG_DSN` when set (new, small wiring in `buildStore`/after `store.Connections`). SQL uses the schema-qualified `fmc_order.order_status`.
6. **Flow tree shape (runtime-valid).** `trigger → action(read, saveAs=order)` whose children run in order: `[decision(fmc-decision, input [order.payment_status], saveAs=decided), set(order.order_id→response...), set(action from decided.action), response(200)]`. Because `action.walkChildren` runs its children sequentially and `decision` stores `decided` then returns non-stop, the subsequent `set` + `response` siblings execute. `action` is set ONLY by the `set(from "decided.action")` node, which exists only because the decision ran.
7. **Response field mounting.** Rather than many `set` nodes, mount the six passthrough fields with one `set` per field from `order.<col>` (order_id, msisdn, order_status, payment_status, payment_amount, product_name) plus one `set` for `action` from `decided.action`. Keep the existing `orders-expedite` flow in the seed (don't break current tests) and ADD the two new flows + JDM + connection.

## Notes / assumptions
- `pgx` extended-protocol int→text binding risk for a numeric msisdn is mitigated with `$1::text` casts in both SELECTs (item 4). If a reviewer prefers coercion changes instead, that is a bigger blast radius; the `::text` cast is the minimal, local fix.
- The task prose says NewHandler also mounts "admin routes" — it does not today; no admin route work is in scope.
- RED metric call sites are already defined in `internal/observ/metrics.go` but not invoked on the hot path; `/metrics` exposing registered collectors satisfies AC (an expected metric NAME is present). Wiring RED middleware is out of scope for this increment.
