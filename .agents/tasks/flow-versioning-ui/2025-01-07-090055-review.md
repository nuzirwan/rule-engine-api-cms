# Flow Versioning UI Implementation

Adds version history, comparison, preview, and rollback functionality to the CMS admin for flow management. The implementation spans a server-side proxy layer (flow controller with `getVersions` and `rollback` endpoints) and a React admin UI (VersionHistory panel, VersionDiff modal, VersionPreview modal, FlowDetailPage). All acceptance criteria from FEAT-001 and FEAT-002 are met: build passes, 235 tests pass (including 61 new tests for this feature).

**Watch for:** One potential issue—the VersionPreview fetches flow detail via `/rule-engine/flows/:id?version=X` but this endpoint doesn't appear to be registered in the routes file (only `/flows/:id/versions` and `/flows/:id/rollback` are new). If the existing flow detail endpoint doesn't support the `?version` query param, preview will fail. **Confidence: likely** — the endpoint may be pre-existing from another FEAT, but worth verifying.

**Verdict**: APPROVED

## High-level view

The server layer adds two proxy endpoints following the established sync.ts pattern: `GET /flows/:id/versions` proxies to `AdminClient.listFlowVersions()`, and `POST /flows/:id/rollback` proxies to `AdminClient.rollbackFlow()`. Error handling classifies 5xx as recoverable (503) and 4xx as non-recoverable (echo status), consistent with existing controllers.

The VersionHistory panel follows SyncPanel's state management pattern: a FetchState discriminated union for loading/error/ok states, useFetchClient for API calls, and Strapi design-system components for layout. Comparison selection (max 2 versions) uses simple array state with a "replace oldest on third selection" policy. Pagination shows first 10 versions with a "Load more" button.

The diff logic is pure TypeScript (no React) in `diff.ts`, making it unit-testable. The `jsonDiff` function performs recursive comparison of objects and arrays, returning structured `DiffEntry` results with path, type, and old/new values. 31 unit tests cover various tree shapes including engine node structures.

The FlowDetailPage is registered at `/flows/:flowId` and wraps VersionHistory with flow metadata header and EnvironmentProvider context. Route registration in admin/src/index.tsx follows the existing lazy-loading pattern.

## Server-side flow controller

The flow controller (`cms/src/plugins/rule-engine/server/src/controllers/flow.ts`) follows sync.ts exactly: factory pattern with strapi + fetchImpl injection, `createClient()` helper that handles missing config by returning 503, and `handleApiError()` that classifies by recoverability. The typed responses (`ListFlowVersionsResponse`, `SetActiveResponse`) are imported from `types/engine.ts`.

Routes registered in `routes/index.ts` at the expected paths:
```
GET  /flows/:id/versions  → flow.getVersions
POST /flows/:id/rollback  → flow.rollback
```

Tests in `flow.test.ts` cover: successful responses, 404 for missing flows, 503 for engine unavailable, and 503 for missing config. Uses nock + httpFetch shim pattern from sync.test.ts.

## VersionHistory panel

State management uses the FetchState/ActionState pattern seen in SyncPanel. Key behaviors:

- Fetch-on-mount via useEffect with flowId dependency
- Comparison selection: `selectedVersions[]` with max 2, toggles via `handleToggleCompare`, replaces oldest on overflow
- Pagination: `displayCount` starts at 10, "Load more" increments by PAGE_SIZE
- Rollback: confirmation modal with danger variant button, refresh list on success
- Error states: distinguishes recoverable (engine unavailable) vs non-recoverable, shows appropriate messaging

The panel integrates VersionDiff and VersionPreview modals inline using Strapi's Modal.Root pattern.

## VersionDiff modal and diff logic

The diff logic in `diff.ts` is cleanly separated:

- `jsonDiff(a, b, basePath)`: recursive comparison, handles primitives/objects/arrays
- `formatValue(value)`: display formatting for diff view
- `groupDiffsBySection(diffs)`: groups by top-level path segment for organized display

The React component in `VersionDiff/index.tsx` computes diffs for tree, fixtures, and metadata separately, then renders with color-coded highlighting (green=added, red=removed, yellow=changed). Uses Badge variants for counts and DiffLine/DiffSection sub-components for structure.

## VersionPreview modal

Fetches flow detail for a specific version and renders FlowCanvasField in read-only mode (`disabled={true}`). Shows metadata header with method/path/version badge and fixtures summary if present.

The endpoint called is `/rule-engine/flows/${flowId}?version=${version}` — this assumes the existing flow detail endpoint supports version query param.

## FlowDetailPage and route registration

FlowDetailPage at `/flows/:flowId` shows:
- Header with method/path, active version badge
- Back navigation
- VersionHistory panel

Route registered in admin/src/index.tsx following the async Component pattern for lazy loading:
```typescript
{
  path: '/flows/:flowId',
  Component: async () => { /* lazy import + EnvironmentProvider wrap */ },
  exact: true,
}
```
