# Gateway Dispatcher Implementation for Phase 3

This PR implements the gateway dispatcher infrastructure for routing flow execution requests to worker pods. The changes add a dispatch config loader, a worker registry that watches K8s Endpoints, an HTTP client with per-group circuit breakers, and integrates everything into httpapi for transparent gateway-mode execution. The implementation is backward compatible—inline mode (the default) continues to work unchanged.

**Watch for:** The worker port (8080) is hardcoded in registry.go rather than configurable [confirmed]. The circuit breaker follows the resilience.go pattern but uses consecutive failures only, not failure ratio [confirmed]. Both are minor and match existing patterns.

**Verdict**: APPROVED

## High-level view

The dispatch config follows existing config patterns: env vars with sensible defaults, validation errors classified as ErrValidation, and duration parsing for timeouts. The k8s client-go dependency is declared in go.mod correctly and only instantiated when gateway mode is active.

The circuit breaker implementation in gateway/circuit.go mirrors internal/connect/resilience.go's structure: per-group breakers (like per-key breakers), configurable threshold and timeout, half-open probing. It omits the failure ratio trip condition that resilience.go has, using only consecutive failures—a reasonable simplification since workers are more homogeneous than arbitrary connections.

The WorkerRegistry correctly watches K8s Endpoints using client-go informers. It parses service names matching `worker-{group}`, extracts ready addresses, and builds service endpoints. Health probes run on a background ticker. State is protected by mutex, and GetWorker returns copies to prevent external mutation.

The Dispatcher checks registry for the worker group, returns WORKER_NOT_FOUND or WORKER_NOT_READY errors with no fallback (per design requirements), and forwards through WorkerClient with trace header propagation. The httpapi integration is clean: a Dispatcher interface allows testing, and the handler branches on dispatch mode early in the request path.

## Dispatch config follows existing patterns

The `internal/config/dispatch.go` file follows the established config pattern:

- Uses `getEnvOrDefault` and `parseDurationOrDefault` helpers consistent with other config loaders
- Returns classified errors via `newErr(Validation, ...)` that integrate with the error hierarchy
- Default values are reasonable: inline mode, 30s startup timeout, 60s request timeout, "flow-workers" namespace, "default" group

The test coverage is thorough: defaults, all env vars, invalid mode, invalid duration strings.

## Circuit breaker aligns with resilience.go pattern

The `gateway/circuit.go` creates per-group circuit breakers following the same sony/gobreaker pattern as `connect/resilience.go`:

```go
// From resilience.go
return gobreaker.NewCircuitBreaker[any](gobreaker.Settings{
    Name:        key,
    MaxRequests: breakerHalfOpenMaxRequests,
    Timeout:     openTimeout,
    ReadyToTrip: func(c gobreaker.Counts) bool {
        if c.ConsecutiveFailures >= threshold {
            return true
        }
        if ratio > 0 && c.Requests >= breakerMinRequests {
            return float64(c.TotalFailures)/float64(c.Requests) >= ratio
        }
        return false
    },
    ...
})
```

The gateway version simplifies to consecutive failures only, omitting the ratio-based trip. This is appropriate because worker groups are more homogeneous than arbitrary external connections—if one worker in a group is failing, they likely all are.

Default values match resilience.go: threshold=5, openTimeout=10s, halfOpenMaxRequests=1.

## WorkerRegistry correctly watches K8s Endpoints

The registry uses client-go informers properly:

- `NewSharedInformerFactoryWithOptions` with namespace filter
- Event handlers for Add/Update/Delete on Endpoints
- Cache sync wait before processing
- Background health check loop with ticker

The endpoint URL construction `http://worker-{group}.{namespace}.svc:8080` uses the K8s DNS pattern correctly. Health probes hit `/healthz` on each worker's service endpoint.

State management is thread-safe: `sync.RWMutex` protects the workers map, and `GetWorker` returns a copy to prevent callers from mutating internal state.

## Dispatcher returns errors when worker unavailable

The dispatcher explicitly checks for worker existence and readiness:

```go
workerState, ok := d.registry.GetWorker(group)
if !ok {
    return nil, &DispatchError{Code: ErrCodeWorkerNotFound, ...}
}
if !workerState.Ready {
    return nil, &DispatchError{Code: ErrCodeWorkerNotReady, ...}
}
```

No fallback logic is present—this matches the design requirement that missing/unhealthy workers should error, not silently degrade.

## Trace headers propagated correctly

The WorkerClient propagates trace headers via `propagateTraceHeaders`:

- X-Request-Id from observ.ScopeFrom(ctx)
- X-Trace-Id from scope or OTel context
- traceparent in W3C format for OTel propagation

The Dispatcher builds the ExecuteRequest with RequestID and TraceID extracted from context before calling the client.

## httpapi integration preserves backward compatibility

The genericFlowHandler branches early based on dispatch mode:

```go
if deps.DispatchConfig != nil && deps.DispatchConfig.Mode == config.DispatchGateway && deps.Dispatcher != nil {
    handleGatewayDispatch(ctx, w, r, fv, input, deps)
    return
}
handleInlineExecution(ctx, w, fv, input, interp, deps)
```

When DispatchConfig is nil or mode is inline, execution proceeds through the interpreter unchanged. This ensures existing deployments work without modification.

The `/internal/execute` endpoint is only mounted when Dispatcher is set (gateway mode), providing a clean internal API for worker-to-worker calls.

## Tests cover main paths

Test coverage is comprehensive:

- **dispatch_test.go**: All default values, env var parsing, invalid modes, invalid durations
- **dispatcher_test.go**: Worker not found, worker not ready, success path, timeout, error propagation
- **client_test.go**: Success, worker errors, HTTP errors, timeout, circuit breaker opens, per-group breakers

## Hardcoded values
